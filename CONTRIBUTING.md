# Website ↔ GitHub article links

A reader who follows a KPHD website link to a companion article on GitHub must have a clear route back at both the top and bottom of that page.

For KPHD-controlled articles:

1. Place the website navigation before the title and repeat it after the references, credits and disclosure.
2. Link back to the originating Field Note when one is known. Also offer **Field Notes** and **Home**. If there is no single originating note, use Field Notes as the return destination.
3. Use absolute production URLs on `https://kelliepatry.com`. Return links must work when someone arrives directly from search, a bookmark or a shared GitHub link.
4. Preserve the article's existing series links, chapter links and conclusion anchors. Website return navigation supplements those reading paths.
5. Before publishing, verify the website-to-GitHub link and the GitHub-to-website links. Check that the top and bottom navigation is readable on desktop and phone.

The four process-series articles return to [How we work with AI](https://kelliepatry.com/notes/how-we-work-with-ai), with Field Notes and Home alongside it.

## Navigation pattern

Repeat this same row at the beginning and end of each companion article:

```markdown
[← Back to “How we work with AI”](https://kelliepatry.com/notes/how-we-work-with-ai) · [Field Notes](https://kelliepatry.com/notes) · [Home](https://kelliepatry.com/)
```

For an article without a specific originating Field Note:

```markdown
[← Back to Field Notes](https://kelliepatry.com/notes) · [Home](https://kelliepatry.com/)
```
