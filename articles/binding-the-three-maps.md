# Binding the three maps

### Every registered database, mapped into the read systems

**KPHD Studio, Los Angeles · 8 November 2026 · working draft v0.1 · binding owner: Claude, by Kellie's direction**

> **What this is.** The studio has three maps of seeing: the model's read map (a path), the architect's 5D and fascia (a structure) and the artist's relation (a comparison). This paper binds the studio's registered databases to those three maps. Every active database gets one read class and, through that class, a role in each map. The registry stays where it is. No new database, tracker or register is created. Authority stays with Supabase and with Kellie.

> **Superseded in part, 8 November 2026.** The ruling GOV-20261108-NOTION-PROJECTION-ONLY (see [One record, one projection](./one-record-one-projection.md)) turns the aliases in section 5 into projection-template names and resolves the duplicate pairs at the match. The read classes and the appendix stand.

**Read the maps:** [How an artist sees](./how-an-artist-sees.md) · [Flip the paper](./flip-the-paper.md) (the read map and the two perspectives) · [The anatomy](./anatomy-of-a-small-business-that-survives-ai.md) (fascia)

## 1. Decisions

Taken 8 November 2026 under executive bias. Each is reversible by a later ruling.

1. **One binding, not a second map.** The binding is one column of meaning per registered database: its read class. The class carries the database's role in all three maps. It lives in this paper and in one Office Notes brief until proven, then folds into the Model Context Map by replacement.
2. **Eight read classes.** Spine, Record, Link, Reference, Seeing, Business, Task, Log. Section 2 defines them. Every one of the 234 active registered databases has exactly one.
3. **Aliases now, renames later, in one pass.** Eleven registered names are unclear: no category prefix, an emoji in place of one, or a prefix that disagrees with the category. Section 5 gives each a read-name. Live titles are not changed yet, because the Model Context Map, the governance control panel and the link-graph routing cite databases by title, and the Supabase registry mirrors Notion titles on sync. The rename is one batched change after a title-reference sweep.
4. **Supabase is the authority list.** The binding is built from the live Supabase registry, 234 Active rows, last synced from Notion on 9 October 2026. Four Notion entries in Testing are not yet in Supabase. They are listed in section 6 and bound provisionally.
5. **The Seeing class gets a read-map row.** Row three of the read-path table, Image read, is written in section 4. It is proposed, not built. Rows one and two came first because they were walked against live pickups. Row three is walked the same way before anything is built.
6. **Measure before mapping further.** The artist's measured half already runs for study images: 64 palette records, 562 derivation links. It has run for zero project photographs. The first binding action is to run it on one project's photographs and have Kellie run the worksheet on the same images, then compare. That test decides whether the Seeing class needs more than a read row.

## 3. How each map reads the classes

### 3.1 The read map: a path

The read map is one row per task type with five columns: read first, read next, stop when, write back, owner. Classes tell a row what kind of thing it is reading.

| Class | Read first | Read next | Stop when | Write back |
| --- | --- | --- | --- | --- |
| Spine | Yes, for system and routing questions | Never browsed | The claim cites a row | Nothing |
| Record | The checkpoint, then the record | The record's open loops and scope lines | Next action has an owner and no blocker | Checkpoint |
| Link | Never first | When a record's state or reason is in question | The link's source and target are both read | Loop next action if it changed |
| Reference | Never first | By citation from a record or a standard | The cited row is read | Nothing |
| Seeing | The image's own record | Palette record, material applications, the row that brought it in | Worksheet filled, or rights not cleared | Palette record, lineage, one-line about |
| Business | On business tasks | Related record | Ask is answered | The business row |
| Task | Second, on resume and recap | Transcript only for exact wording | Actions binned | Meeting record, recap, task |
| Log | Never | As evidence for a claim | Claim is supported | Run receipt |

### 3.2 5D and fascia: a structure

5D is the model where every component carries its own classification, tags, attributes and scenes. Fascia is the typed, directed links that carry change between records.

- **Record is the component.** A project, a drawing set, a plan drop, a model. Each carries its own information and its own state.
- **Reference is the classification source.** Phase codes, deliverable taxonomy, SketchUp standardisation, specification types. A component's tags come from here. In Supabase the classification tables and the record registers (18 register codes, section 7) are the live form.
- **Link is the fascia.** Decision logs, handoffs, discussions, risk flags, learnings. When a decision changes, the link says which records it touches. The live form is the link graph and the lineage tables.
- **Seeing enters the structure at one point.** A chosen finish becomes a material application on a project object, with a role: made of, substrate, finished with, coated with, edged with, upholstered with. From there fascia carries it to the schedule, the sheet and the spec. Six roles exist in the live vocabulary, all still candidates. 149 material applications are recorded.
- **Log is evidence on a link**, never a component.

### 3.3 The relation: a comparison

The artist's map reads the Seeing class and only the Seeing class. It reads in the worksheet order: subject, composition, value, colour, light, space, mark, rhythm, meaning. It does not read a database as a list. It reads one image at a time and compares. The read map carries the result back as a record, in the Image read row.

Proposed. Walk it against one real image before building anything.

| Task type | Read first | Read next | Stop when | Write back | Owner |
| --- | --- | --- | --- | --- | --- |
| Image read | The image's own record: media_assets row or IMG row. Id, rights and release state, credit, caption. ### 4.5 Spine check for the class

| Record | id | state | one-line summary | supersedes |
| --- | --- | --- | --- | --- |
| core.media_assets | asset_id, asset_key | ingest, screening, sensitivity, release (four) | caption, alt_text | none; archived_at only |

## 7. The other two registries

**Knowledge registry.** 21 hubs in core.knowledge_registry. Open and canonical hubs bind as Reference. Restricted and security-enclave hubs (client intelligence, people intelligence, project intelligence briefs, questionnaire responses, emotional milestones, the proforma baseline) bind as Business or Record with their restriction carried. The read map reads a restricted hub only on a task that names it.

**Record registers.** 18 register codes in core.record_registers. They are the Record class's own vocabulary: CO, DWG, FOR, LTR, PAY, PKG, PRES, RFI, RPT, SCH, SPEC, SUB map to deliverables and construction-administration series. SKP maps to the model. MTG and NOTE map to Task. IMG and RND map to core.media_assets, so the Seeing class has two register codes already. TASK is reserved.

## 9. The classification rule

Applied to the clean name, category and usage type of each Active row, in this order. First match wins.

```text
Seeing     name matches image | visual | pinterest | render | 3d | material stud | design reference |
           zeitgeist | cultural reference | design movements | asset library | figma | creative os | photo
Link       name matches decision | handoff | discussion | risk | relation map | soft flags |
           change proposals | learnings | lessons
Task       category TSK, or name matches intake | triage | output tracker | email | calendar | checklist |
           work blocks | action items | daily briefing | brandstorm | routing queue
Log        usage type Passive Logging, or name matches performance | metrics | health | anomaly | error |
           audit | experiments | chat log | run log | stall
Spine      category SYS, or name matches registry | custom agents | skills index | hubs
Business   category BIZ
Record     category PRJ, or name matches documents | model tracker | billing | expense | invoice |
           payments | time tracker | occupancy
Reference  everything else
Read-name  strip leading symbols and the registry suffix; if no CAT | prefix, prepend the category's three letters
```
